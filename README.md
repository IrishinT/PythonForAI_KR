## О проекте

Приложение прогнозирует вероятность дождя на следующий день по сегодняшним метеонаблюдениям. Пользователь может получить прогноз в настольном приложении на PySide6 или в Telegram-боте на aiogram. Оба клиента отправляют данные в один API на FastAPI.

Модель использует семь полей: место наблюдения, влажность, давление и направление ветра в 15:00, минимальную температуру, количество осадков и максимальную скорость порыва ветра.

## Данные и результаты

Для обучения использован датасет [Rain in Australia](https://www.kaggle.com/datasets/jsphyg/weather-dataset-rattle-package). Исходные наблюдения сохранены в [data/raw/weatherAUS.csv](data/raw/weatherAUS.csv). Целевое поле `RainTomorrow` показывает, был ли дождь на следующий день.

Выпуск **1.1.0** содержит логистическую регрессию, дерево решений, KNN, случайный лес и многослойный перцептрон. Все модели обучены на семи полях. MLP показала наибольший ROC-AUC на тестовой выборке (**0,8848**) и стала моделью по умолчанию для этого выпуска. Её F1 составила **0,6218**, а accuracy — **85,56%**. [Отчёт о сравнении моделей](ml/training/reports/models_metrics_comparison.csv)

### FastAPI

```text
python -m uvicorn business.api:app
```

Документация API доступна в [Swagger UI](http://127.0.0.1:8000/docs). Маршрут `GET /health` показывает состояние сервиса и версию модели по умолчанию. Маршрут `POST /predict` принимает наблюдения и возвращает вероятность дождя.

В теле `POST /predict` передаются погодные наблюдения. Необязательные параметры `model_version` и `model_id` задают выпуск и конкретную модель. Ответ содержит `model_version` и `model_id` использованной модели.

| Запрос | Модель |
| --- | --- |
| `POST /predict` | Лучшая модель выпуска из `artifacts/latest.json`, загруженного при запуске API |
| `POST /predict?model_version=1.1.0` | Лучшая модель выпуска `1.1.0` |
| `POST /predict?model_version=1.1.0&model_id=random-forest` | Случайный лес выпуска `1.1.0` |
| `POST /predict?model_id=knn` | KNN из выпуска, загруженного при запуске API |
| `POST /predict?model_version=1.0.2` | Единственная модель выпуска `1.0.2` с идентификатором `default` |

`GET /models` показывает доступные идентификаторы и модель по умолчанию. Чтобы посмотреть другой выпуск, передайте `model_version`, например `GET /models?model_version=1.1.0`. Для отсутствующей версии или модели API возвращает `404`, для неверного формата параметров — `422`.

`GET /models/versions` возвращает список выпусков, модели каждого выпуска и последнюю опубликованную версию. `GET /models/metrics?model_version=1.1.0&model_id=mlp` возвращает числовые метрики выбранной модели и идентификаторы доступных графиков. Готовый PNG можно получить отдельным запросом, например `GET /models/metrics/roc?model_version=1.1.0&model_id=mlp`. Доступные графики — `roc`, `precision-recall`, `learning-curve` и `confusion-matrix`.

### Настольное приложение

После запуска API откройте второй терминал с тем же виртуальным окружением.

```text
python -m presentation.desktop
```

Адрес API задаётся в `WEATHER_API_URL` в корневом `.env`. Параметр `--api-url` при запуске имеет приоритет.

Переключатели версии и модели действуют на вкладки «Прогноз» и «Метрики». Зелёным выделена модель с наибольшим ROC-AUC в последнем выпуске. На вкладке «Метрики» показаны числовые показатели и готовые графики выбранной модели.

### Telegram-бот

Если в корне проекта ещё нет файла `.env`, создайте его по образцу [`.env.example`](.env.example). Запишите токен от `@BotFather` в переменную `TELEGRAM_BOT_TOKEN`. Если API работает на другом сервере, укажите его адрес в `WEATHER_API_URL`. Файл `.env` исключён из Git.

Откройте личный чат с ботом и отправьте `/start`.

## Обучение и исследование признаков

После установки зависимостей для обучения выполните команды из корня проекта.

```text
python -m ml.analysis.feature_importance
python -m ml.training.preprocessing
python -m ml.training.train_models
```

Первая команда оценивает важность полей и сравнивает полный набор с сокращённым. Подготовка данных обновляет выборки в `data/processed/`. Обучение сохраняет все модели в одном выпуске в `artifacts/`. Файл `release.json` хранит идентификаторы моделей и указывает модель с наибольшим ROC-AUC на тестовой выборке. Если `1.1.0` уже существует, следующий запуск обучения создаёт `1.1.1` или следующий свободный патч-выпуск. API считывает новый выпуск по умолчанию при следующем запуске.

Графики сохраняются рядом с моделью в папке `charts/`. ROC, Precision–Recall и матрица ошибок построены на тестовой выборке. Для кривой обучения модели с сохранёнными гиперпараметрами обучаются на стратифицированных подвыборках разного размера, а ROC-AUC измеряется на этих подвыборках и на одной фиксированной отложенной выборке. Команда `python -m ml.training.model_diagnostics` пересоздаёт PNG для существующих выпусков по подготовленным данным.
