## О проекте

Приложение прогнозирует вероятность дождя на следующий день по сегодняшним метеонаблюдениям. Пользователь может получить прогноз в настольном приложении на PySide6 или в Telegram-боте на aiogram. Оба клиента отправляют данные в один API на FastAPI.

Для прогноза используются место наблюдения, влажность, давление и направление ветра в 15:00, минимальная температура, количество осадков и максимальная скорость порыва ветра.

## Данные и результаты

Для обучения использован датасет [Rain in Australia](https://www.kaggle.com/datasets/jsphyg/weather-dataset-rattle-package). Исходные наблюдения сохранены в [data/raw/weatherAUS.csv](data/raw/weatherAUS.csv). Целевое поле `RainTomorrow` показывает, был ли дождь на следующий день.

Проект обучает логистическую регрессию, дерево решений, KNN, случайный лес и многослойный перцептрон. В каждом новом выпуске модель с наибольшим ROC-AUC на тестовой выборке становится моделью по умолчанию. [Отчёт о сравнении моделей](ml/training/reports/models_metrics_comparison.csv)

## Локальный запуск

Из корня проекта создайте виртуальное окружение с Python 3.12.

```text
python -m venv .venv
```

Активируйте `.venv` или выберите её интерпретатор в IDE и установите зависимости.

```text
python -m pip install -r requirements.txt
```

Для настройки клиентов и обучения создайте `.env` по образцу [`.env.example`](.env.example). Для локального API клиенты по умолчанию используют `http://127.0.0.1:8000`. Адрес можно изменить через `WEATHER_API_URL`.

### FastAPI

```text
python -m uvicorn business.api:app
```

Основные маршруты описаны в [Swagger UI](http://127.0.0.1:8000/docs).

- `GET /health` показывает состояние сервиса и активную модель.
- `GET /models/versions` показывает доступные выпуски и модели. `GET /models` показывает модели одного выпуска.
- `POST /predict` принимает погодные наблюдения и возвращает вероятность дождя и идентификаторы использованной модели. Для выбора передайте `model_version` и `model_id`. По умолчанию используется лучшая модель последнего выпуска.
- `GET /models/metrics` возвращает метрики выбранной модели. `GET /models/metrics/{chart_id}` отдаёт готовый PNG.
- `POST /models/training` запускает обучение в фоне, а `GET /models/training` показывает его этап, прогресс и результат. Оба маршрута требуют `X-Master-Key`. Задайте `WEATHER_MASTER_KEY` в `.env` перед запуском API.

Подробный журнал запросов и обучения сохраняется в `logs/backend.log` с ротацией. Папку можно изменить через `WEATHER_LOG_DIR`.

### Настольное приложение

После запуска API откройте второй терминал с тем же виртуальным окружением.

```text
python -m presentation.desktop
```

Выбор выпуска и модели применяется к прогнозу и метрикам. На вкладке «Обучение» можно запустить задачу по мастер-ключу и следить за прогрессом. Если `WEATHER_MASTER_KEY` задан в `.env`, приложение подставит его при запуске. Параметр `--api-url` имеет приоритет при выборе адреса API.

### Telegram-бот

Укажите токен от `@BotFather` в `TELEGRAM_BOT_TOKEN` и запустите бота в отдельном терминале.

```text
python -m presentation.telegram_bot
```

В личном чате `/start` открывает клавиатуру, `/help` показывает справку и команды, а `/about` рассказывает, что делает бот. Через `/forecast`, `/model` и `/metrics` можно получить прогноз, выбрать модель и посмотреть её метрики.

Для обучения укажите тот же `WEATHER_MASTER_KEY`, что на API, и перечислите Telegram ID администраторов в `TELEGRAM_ADMIN_IDS` через запятую. Свой ID можно узнать через `/id`. После перезапуска бота используйте `/train` для запуска и `/training_status` для проверки статуса.

## Обучение и исследование признаков

Для запуска анализа, подготовки данных и обучения выполните команды из корня проекта.

```text
python -m ml.analysis.feature_importance
python -m ml.training.preprocessing
python -m ml.training.train_models
```

Подготовленные выборки сохраняются в `data/processed/`. Обучение создаёт выпуск в `artifacts/` с моделями, метриками и PNG-графиками. После публикации API подхватывает новый выпуск без перезапуска. Для пересоздания графиков существующих выпусков используйте `python -m ml.training.model_diagnostics`.

## Тесты

После установки зависимостей API и Telegram-бота запустите из корня проекта:

```text
python -m unittest discover -s tests -v
```

Тесты проверяют валидацию погоды, выбор модели, выдачу графиков, авторизацию и обучение, публикацию выпусков и сценарии Telegram-бота. Для проверки маршрутов бота используется тестовый транспорт Telegram.
