## О проекте

Приложение прогнозирует вероятность дождя на следующий день по сегодняшним метеонаблюдениям. Пользователь может получить прогноз в настольном приложении на PySide6 или в Telegram-боте на aiogram. Оба клиента отправляют данные в один API на FastAPI.

Модель использует семь полей: место наблюдения, влажность, давление и направление ветра в 15:00, минимальную температуру, количество осадков и максимальную скорость порыва ветра.

## Данные и результаты

Для обучения использован датасет [Rain in Australia](https://www.kaggle.com/datasets/jsphyg/weather-dataset-rattle-package). Исходные наблюдения сохранены в [data/raw/weatherAUS.csv](data/raw/weatherAUS.csv). Целевое поле `RainTomorrow` показывает, был ли дождь на следующий день.

В проекте сравниваются логистическая регрессия, дерево решений, KNN, случайный лес и многослойный перцептрон. В API используется MLP версии **1.0.2**, обученная на семи полях. На тестовой выборке она получила **ROC-AUC 0,8848**, **F1 0,6218** и **accuracy 85,56%**. [Отчёт о сравнении моделей](ml/training/reports/models_metrics_comparison.csv)

## Локальный запуск

Из корня проекта создайте виртуальное окружение с Python 3.12. Если системная команда называется `python3`, используйте её при создании окружения.

```text
python -m venv .venv
```

Активируйте окружение или откройте терминал IDE с выбранным интерпретатором из `.venv`. Затем установите зависимости.

```text
python -m pip install -r requirements.txt
```

Для запуска отдельных компонентов можно установить только нужный набор зависимостей.

| Компонент | Файл для `pip install -r` |
| --- | --- |
| API с готовой моделью | [business/api/requirements.txt](business/api/requirements.txt) |
| Настольный клиент | [presentation/desktop/requirements.txt](presentation/desktop/requirements.txt) |
| Telegram-бот | [presentation/telegram_bot/requirements.txt](presentation/telegram_bot/requirements.txt) |
| Обучение и анализ | [ml/requirements.txt](ml/requirements.txt) |

### FastAPI

```text
python -m uvicorn business.api:app
```

Документация API доступна в [Swagger UI](http://127.0.0.1:8000/docs). Маршрут `GET /health` показывает состояние сервиса и версию модели. Маршрут `POST /predict` принимает наблюдения и возвращает вероятность дождя.

### Настольное приложение

После запуска API откройте второй терминал с тем же виртуальным окружением.

```text
python -m presentation.desktop
```

Адрес API задаётся в `WEATHER_API_URL` в корневом `.env`. Параметр `--api-url` при запуске имеет приоритет.

### Telegram-бот

Если в корне проекта ещё нет файла `.env`, создайте его по образцу [`.env.example`](.env.example). Запишите токен от `@BotFather` в переменную `TELEGRAM_BOT_TOKEN`. Если API работает на другом сервере, укажите его адрес в `WEATHER_API_URL`. Файл `.env` исключён из Git.

Запустите бота в отдельном терминале с тем же виртуальным окружением.

```text
python -m presentation.telegram_bot
```

Откройте личный чат с ботом и отправьте `/start`.

## Docker Compose

Укажите `TELEGRAM_BOT_TOKEN` в `.env` по образцу [`.env.example`](.env.example) и запустите из корня проекта.

```text
docker compose up -d --build
```

Для доступа к API с другого компьютера задайте в `.env` `WEATHER_API_BIND=0.0.0.0` и нужный `WEATHER_API_PORT`.

## Обучение и исследование признаков

После установки зависимостей для обучения выполните команды из корня проекта.

```text
python -m ml.analysis.feature_importance
python -m ml.training.preprocessing
python -m ml.training.train_models
```

Первая команда оценивает важность полей и сравнивает полный набор с сокращённым. Подготовка данных обновляет выборки в `data/processed/`. Обучение сравнивает модели и сохраняет лучшую версию в `artifacts/`. Для запуска API можно использовать уже сохранённую модель.
